## 1. The project in one paragraph

A PCB in the Shugart SA400 floppy-drive motherboard form factor (5.5 × 5.0 in, same 34-pin card-edge tab J1 and
4-pin Mate-N-Lok power header J2 on the rear edge) that plugs onto a TRS-80 Model I floppy ribbon as a fifth
"drive" and shows, on LEDs, which drive is selected (red) and when WRITE GATE is asserted for it (green). 74LS
logic, all through-hole, 5 mm LEDs, socketed DIPs. Protected so that the external supply cannot hurt the
Expansion Interface: PTC, P-MOSFET reverse-polarity switch, 5.6 V rail clamp, 470 Ω series resistor in every
bus line. KiCad 10 project generated by a Python generator; fabricated and assembled at JLCPCB.

## 4. Open items that gate the next steps

1. **J2 handedness — bench check, before any power on any board.** Header pushed into its holes (not
   soldered), drive power plug on, DMM continuity from the plug's **yellow (+12 V)** wire to the pad printed
   **+12V**. Pass → solder it where it is. Fail (lands on +5V) → the header belongs on the *other* side of the
   board; for v0.2.4 flip `J2_PIN1_X`/`J2_PIN_DIR` in `gen/config.py` and rebuild. Why: moving a header
   between sides mirrors it, and the header's own pin-1 side was never verified. `docs/ASSEMBLY.md` §Polarity.
2. Three ASSUMED dimensions to measure on a v0.2.3 board: `J1_TAB_CORNER_GAP` (5.08), `J1_KEY_SLOT_W` (0.91),
   `J2_DRILL` (2.1; TE lists the 350211-1 post at 1.6 mm). All in `gen/config.py`, each with its source comment.
3. J2 part for v0.2.4: right-angle **TE 1-641737-1** (TE shows "contact distributor"; LCSC availability
   unknown) or vertical **350211-1** (LCSC C305826, in JLCPCB stock) — same pads and courtyard. BOM leaves the
   LCSC number blank on purpose.
4. Test results from the testing session → decide: v0.2.4 re-spin (J2 only) vs go straight to v0.3.
5. v0.3 (`V0.3_PLAN.md`): four 8-bit common-cathode LED bar modules (Ven has Amazon B0GT4DWRX1), one per drive,
   driven by 74HCT244s gated by the drive-select nodes; 74HCT14 receivers; six more bus lines (MOTOR ON, STEP,
   DIRECTION, TRACK 00, WRITE PROTECT, INDEX) each through 470 Ω; 74LS123 to stretch STEP/INDEX; 1N4148 with
   D12. Open before starting: module colour split and on-board resistor value (Ven to confirm), F4 (D11 value).

## 5. How the project is built (do not hand-edit the KiCad files)

`gen/config.py` is the single source of truth (every dimension with its source in a comment; `VERSION`).
`gen/design.py` places parts and defines nets; `gen/router.py` routes; `gen/pcb_writer.py` / `gen/sch_writer.py`
write the KiCad files; `gen/postprocess.py` runs under KiCad's Python (zone fill, F8 metadata).

```powershell
cd C:\Users\ven\Desktop\Projects\_claude\sa400-led-monitor\sa400_led_monitor
python gen\verify.py  --kicad-bin "C:/Program Files/KiCad/10.0/bin"   # THE release gate (see below)
python gen\outputs.py --kicad-bin "C:/Program Files/KiCad/10.0/bin"   # renders, copper views, STEP, schematic PDF
python pdf\build_pdf.py                                                # design PDF, LuaLaTeX (fontspec/circuitikz/DejaVu)
```

`verify.py` = build → postprocess → KiCad DRC with schematic parity (must be 0/0/0) → ERC (0) → 47/47
footprint↔symbol links → F8-metadata emulation → docs non-empty → version strings consistent across docs and a
CHANGELOG entry for `VERSION` at the top (ASSEMBLY.md and TEST_PLAN.md are exempt — they name older hardware on
purpose) → gerbers + drill → JLCPCB CPL (adds U1A/U2A/U3A socket rows) → BOM↔CPL cross-check → zips the gerbers.
Exit 0 ok, 1 a gate failed (it says which), 130 Ctrl-C. KiCad 10.0.6 on Windows; on Linux the AppImage from
github.com/pkgforge-dev/KiCad-AppImage (extract with `--appimage-extract`, pass `<dir>/bin`).

**Version bump protocol:** change `VERSION` in `config.py`; add the `## vX.Y.Z — date — title` entry at the top
of `docs/CHANGELOG.md`; update the version in every doc header (the gate catches stragglers); rebuild; run
`outputs.py` and `build_pdf.py`; the design PDF must carry a footer on every page (name · created/updated · version
· Page X of Y — `pdf/template.tex` does this).

**JLCPCB:** upload exactly three files — `output/<project>_vX.Y.Z_gerbers_JLCPCB.zip`, `output/assembly/BOM_jlcpcb.csv`,
`output/assembly/CPL_jlcpcb.csv`. Never the project zip (an order was cancelled for that on 2026-10-05). Order
options and the PCBA remark are in `docs/FABRICATION.md`. Economic PCBA is enough from v0.2.4 (all parts on top).

## 7. Hard-won facts (don't rediscover these)

- **J1 card edge** follows the 3M TS-0010-14 recommended layout: tab 45.59 mm, 17 fingers per side at 2.54,
  1.40 wide, 10.16 reach, copper set back 0.66 from the edge (JLCPCB 30° bevel), key slot 0.91 × 11.43 between
  pins 4/6, two Ø1.6 non-plated clip holes under pins 2 and 34, pin 2 at the right viewed from the component
  side with fingers away, odd pins = ground on the solder side. Tab depth = rear recess = 11.43 mm.
  `docs/MECHANICAL.md` has every number with its source.
- **Monitored bus pins:** 10 DS1, 12 DS2, 14 DS3, 6 DS4, 24 WRITE GATE (active-low, open-collector 7438 drivers
  on the EI, 150 Ω terminator at the last drive). No terminator on this board. Nothing on the board drives the
  bus; worst case into an EI driver is ≤ 11 mA through the 470 Ω.
- **Signal path:** finger → 470 Ω (R14–R18) → 10 k pull-up + 74LS14 → DSn/WG active-high → 74LS06 (red, OC)
  and 74LS00 (green = DSn·WG) sinking the LEDs; 470 Ω LED series (≈ 5.5 mA with the standard-brightness LEDs
  JLCPCB stocks).
- **Power:** J2-4 +5 V → F1 PTC 0.5 A → Q1 IRF4905PBF P-MOSFET (D in, S out, G to GND; TO-220 pin 1 = gate =
  square pad; metal tab toward the J2 edge) → +5 V rail with D11 1N5339B 5.6 V clamp, C6, C4. J2-1 +12 V only
  lights D12 through R19 2k2. Budget ≈ 45 mA on +5 V.
- **Footprint/symbol linking:** deterministic symbol UUIDs (`uuid5` of the reference), footprint `(path "/<uuid>")`,
  sheetname "/", sheetfile and unit-pin metadata written by `postprocess.py` — that is what makes F8 report no
  changes. `postprocess_check.py` emulates the comparison.
- **TO-220 vertical convention:** pin 1 at −x ⇒ metal tab at −y, body spans y −3.15…+1.25 relative to the pin
  row (Vishay drawing, KiCad `TO-220-3_Vertical`). v0.2.2 drew it wrong; JLCPCB's render was right.
- **Mistakes already made once:** inferring J1 geometry instead of citing the standard; shipping empty docs
  (gate now checks size); uploading the project zip as gerbers; assuming "the keyed plug guarantees the pin
  mapping" for J2 (it guarantees plug-pin-1 ↔ header-pin-1, not which end that is on the footprint).
